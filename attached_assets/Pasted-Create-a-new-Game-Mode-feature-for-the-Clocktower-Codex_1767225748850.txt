### Step 2: Player Names
- Generate input fields for each player based on count

- Allow users to edit names or leave defaults
- "Start Game" button when ready

## 2. GAME VIEW (Main Tracking Interface)

After setup, show the active game view:

### Player List Display
- Show all players in a scrollable list or grid
- Each player card shows:
  - Player name (large, tappable)
  - Claim badges (if any claims added)
  - Status indicator: Alive (default) / Dead
  - Quick icons showing: has notes 📝, has claims 🎭, vote count

### Player Card - Expanded View
When user taps a player name, open a modal/drawer with:

#### A. NOTES SECTION
- Free-form text area for general notes
- Auto-saves on change
- Placeholder: "Add notes about this player..."

#### B. CLAIM LIST
- Header: "Claims" with "+ Add Claim" button
- Clicking "Add Claim" opens a searchable character picker:
  - Search box filters all characters from game-data.ts
  - Show character name + team color (Townsfolk=blue, Outsider=teal, Minion=orange, Demon=red)
  - Tapping a character adds it to this player's claim list
- Display claims as removable badges/chips
- Allow MULTIPLE claims per player (players often claim multiple things)
- Show character icon/token if available

#### C. VOTING RECORD
- Header: "Voting Record" with "+ Add Vote" button
- Clicking "Add Vote" opens a two-step flow:

Step 1 - Select Nominee:
  - Show list of all players in current game
  - User taps to select who was NOMINATED (on the block)
  
Step 2 - Record Vote:
  - Two buttons: "✋ Voted" or "✗ Did Not Vote"
  - This records: "[Player] voted/didn't vote on [Nominee]"

- Display voting history as a list:
  - "Day 1: Voted to execute Player 3"
  - "Day 1: Did not vote on Player 5"
  - Include optional "Day #" selector to organize by game day

## 3. DATA STRUCTURE

interface GamePlayer {
  id: string;
  name: string;
  isAlive: boolean;
  notes: string;
  claims: string[]; // Array of character IDs
  votes: VoteRecord[];
}

interface VoteRecord {
  odae: number; // Game day
  nomineeId: string; // Player ID who was nominated
visitedroteVoted: boolean; // true = voted, false = did not vote
}

interface Game {
  id: string;
  createdAt: Date;
  playerCount: number;
  breakdown: { townsfolk: number; outsiders: number; minions: number; demons: number };
  players: GamePlayer[];
  currentDay: number;
}

## 5. ADDITIONAL FEATURES

### Player Status Toggle
- Tap-and-hold or dedicated button to mark player as Dead
- Dead players show with strikethrough or grayed styling
- Dead players can still have notes/claims viewed

### Day Tracker
- Add a "Day #" indicator at top of game view
- "Next Day" button to increment
- Voting records automatically tag with current day

### Game Persistence
- Save game state to localStorage so it survives page refresh
- Option to "End Game" which clears the current game
- Consider "Game History" to review past games (optional/future)

## 6. NAVIGATION

- Add "Game" to the main navigation alongside Home, Scripts, Reference
- If no active game, show "New Game" setup button
- If game is active, go directly to game view with "End Game" option
